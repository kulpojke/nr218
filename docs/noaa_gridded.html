PROVISIONAL — NOAA gridded weather forecasts in QGIS

An HRRR exploration using supplied local data

PROVISIONAL: as in, not done!

This is a draft lesson, not yet fully tested. It follows the trajectory of dynamical.org’s NOAA HRRR 48-hour virtual forecast notebook, adapted for QGIS.

So don’t get worked up if this lesson crashes and burns

0.1 What are we exploring?

We will be examining some basic concepts in geo-spatiotemporal data analysis, using meterological data.

A weather forecast is a collection of grids containing different variables, elevations, and forecast times. We will examine a weather map, make a point forecast, (and not today) perform rainfall calculations, examine vertical structure, create a storm-track summary, and create an animation. We will use NOAA’s High-Resolution Rapid Refresh (HRRR) data. HRRR uses a 3 km grid over the contiguous United States in a Lambert conformal conic projection.

By the end of the proposed exercise, you should be able to inspect a multidimensional weather dataset, explain forecast timing, symbolize a weather variable, sample a location, and calculate differences and maxima across forecast hours.

0.1.1 Three kinds of time

  • Initialization time: when the forecast run starts.
  • Lead time: how far into the future that run predicts.
  • Valid time: the time being predicted: initialization plus lead time.

For example, if the run initialized at 2024-05-21 18:00 UTC, at lead hour 4, is valid at 2024-05-21 22:00 UTC. Two forecasts can have the same valid time but different initialization times. Keep all times in UTC throughout this exercise.

0.1.2 File naming conventions

The file’s names explain their contents. In hrrr.20240521/hrrr.t18z.wrfsfcf04.grib2, The directory gives the date. The pieces of the filename are:

  • hrrr: the model
  • t18z: the initialization time, 18:00 UTC
  • wrfsfc: the product type, the 2D surface-level file (other types include wrfprs for pressure levels, wrfnat for native levels, and wrfsub for sub-hourly)
  • f04: the forecast hour, meaning a 4-hour lead time

So this file holds the forecast valid at 18Z + 4 h = 22:00 UTC, on the date of the folder it sits in (2024-05-21). The .subset part was added while extracting subsets of the data for this tutorial.

0.1.3 What the dang is a GRIB file anyway?

GRIB (GRIdded Binary) is a World Meteorological Organization (WMO) format built for sending weather model grids over slow telecom links, where data moved as discrete messages, like telegrams. A GRIB message is a self-contained unit holding one gridded field: one variable, at one level, at one time (for example, 2 m temperature valid at 22Z). Each message carries its own header describing the grid, variable, time, and packing, followed by the packed values and an end marker (7777).

A GRIB file is just many messages concatenated, with no file-level header. NOAA’s .idx files list each message’s byte offset, so you can download or subset only the messages you need. In GDAL and QGIS, each message appears as a band, so a file holds one forecast hour, and its bands are the different fields and levels.

All 100 files and 581 bands passed GDAL 3.12.2 metadata/time/grid checks and a sample-window decode per band; see noaa_gridded_data/validation.json for band descriptions and units. import re, os
from qgis.core import (QgsVectorLayer, QgsFeature, QgsProject,
                       QgsVectorFileWriter)
from qgis.utils import iface

src = iface.activeLayer()
pat = re.compile(r'wrfsfcf(\d+)\.subset_(\d+)$')

# band number -> column name
names = {1: "MXUPHL", 2: "TMP", 3: "DPT"}

fmap = {}
for f in src.fields():
    m = pat.search(f.name())
    if m:
        fmap[f.name()] = (int(m.group(1)), int(m.group(2)))

bands = sorted({b for _, b in fmap.values()})
hours = sorted({h for h, _ in fmap.values()})

fields = "&".join(["field=fid:integer", "field=fhour:integer"] +
                  [f"field={names.get(b, f'subset_{b}')}:double" for b in bands])
out = QgsVectorLayer("NoGeometry?" + fields, "hrrr_long", "memory")
prov = out.dataProvider()

new_feats = []
for sf in src.getFeatures():
    rows = {}
    for name, (h, b) in fmap.items():
        rows.setdefault(h, {})[b] = sf[name]
    for h in hours:
        nf = QgsFeature(out.fields())
        nf.setAttributes([sf.id() if src.fields().indexOf("fid") < 0 else sf["fid"], h] +
                         [rows[h].get(b) for b in bands])
        new_feats.append(nf)

prov.addFeatures(new_feats)
out.updateExtents()
QgsProject.instance().addMapLayer(out)

path = os.path.join(os.path.expanduser("~"), "hrrr_long.csv")
opts = QgsVectorFileWriter.SaveVectorOptions()
opts.driverName = "CSV"
err = QgsVectorFileWriter.writeAsVectorFormatV3(
    out, path, QgsProject.instance().transformContext(), opts)
print("Saved to", path, err[0])

  1. Now open the attribute table to hrrr long and take a look.

  2. Export as a csv.

  3. Open the csv in Excell (or whatever you want to use). Plot TMP and DPT against lead time (fhour).

Discuss: When does the dew point fall most sharply? Does temperature change at the same time?

1.1 Turn accumulated precipitation into an interval amount

Use Tampa at longitude −82.46, latitude 27.95, and initialization 2024-10-09 00:00 UTC.

The notebook variable total_precipitation_run_total_surface corresponds here to the APCP:surface:0-HH hour acc fcst record (or the equivalent interval in days at hours 0, 24, and 48). The download selects this run-total record, excluding shorter-interval APCP records. Verify its metadata. For liquid-water equivalent, 1 kg/m² equals 1 mm of water depth.

  1. Load two consecutive accumulated-precipitation grids from the same run. Confirm matching grid alignment, units, and accumulation origin.

  2. In Raster Calculator, subtract the earlier grid from the later grid. The downloaded Milton files use band 1 for reflectivity and band 2 for precipitation. Select band 2 directly, or first extract the APCP bands as single-band working rasters. For single-band layers renamed accum_f005 and accum_f006:

    "accum_f006@1" - "accum_f005@1"

  3. If the input unit is mm, this result is the interval amount in mm. Divide by elapsed seconds for mm/s, or by elapsed hours for mm/hour. For a one-hour interval, divide by 3600 for mm/s.

  4. Sample both the accumulated and interval grids at Tampa. Repeat for the run to build the two series shown in the notebook.

Do not subtract grids from different initialization times. Check negative differences for resets, missing values, or mismatched assets. Leave the first interval undefined unless its starting accumulation is known. A label saying “hourly rainfall” is insufficient without checking the interval length.

1.4 Summarize rotating-storm potential across the forecast

Return to surface-group variable maximum_updraft_helicity_3000_0m, initialization 2025-03-14 12:00 UTC, over longitude −95 to −80, latitude 30 to 42. Use the MXUPHL:3000-0 m above ground band and confirm its units. These are hourly interval maxima; the temporal maximum combines those intervals.

  1. Load the MXUPHL band from every available lead-hour file through hour 48 from that one run. Extract or select only that band for each input, not the temperature or dew-point bands.
  2. Check that the rasters use the same CRS, pixel size, origin, and extent.
  3. Run Cell statistics with the statistic Maximum, using those slices as inputs and a matching reference raster. Record the NoData policy; missing hours make the temporal maximum incomplete.
  4. Display the output over 25–250 m²/s², with values at or below 25 transparent.

This calculates the largest value at each cell over time. The result is a forecast swath of updraft rotation, not an observed tornado track or a tornado probability. Record how many forecast hours contributed.

1.5 Animate Hurricane Milton’s forecast

Use composite reflectivity from initialization 2024-10-09 00:00 UTC, across the forecast, over longitude −88 to −79, latitude 24 to 31.

  1. Prepare one raster layer per valid hour, with consistent extent and grid. The notebook reduces spatial detail for speed; start with native-resolution regional subsets here and evaluate performance.
  2. Apply the same 5–70 dBZ symbology and transparency to every layer.
  3. In each layer’s Temporal properties, enable temporal control and assign a fixed range corresponding to its valid hour. Treat the one-hour display window as an animation convention for an instantaneous field.
  4. Open the Temporal Controller, set a one-hour step, and test a few frames. Check range boundaries so adjacent hours do not overlap unintentionally.
  5. Add a visible valid-time label and keep the map extent and color range fixed. Preview the sequence before exporting frames.

The temporal setup needs testing in the selected QGIS version. See QGIS raster properties for available modes.

Discuss: What moves between frames? Which apparent changes could result from changing symbology rather than changing weather?

1.6 Extend the investigation

Choose one direction after the main workflow is verified:

  • Map the forecast maximum of hail size or wind gust, checking the variable’s units and definition.
  • Sample incoming shortwave radiation through time to identify rapid changes relevant to solar generation.
  • Compare forecast and analysis fields at matching valid times, units, and grid locations. An analysis is another modeled estimate, not independent ground truth.
  • Use Zonal statistics to summarize a selected field over a watershed or county. For precipitation, explain why summing cell depths is not a rainfall volume without accounting for cell area.

Save the QGIS project, source metadata, derived rasters, a labeled map, and a brief explanation of initialization versus valid time.
